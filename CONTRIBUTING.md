# Contributing to backend

Start with this repository's README and the campaign service's scope contract. A contribution should state which asset behavior it checks, retain raw route outcomes, and distinguish synthetic, simulated and confirmed observations. Add boundary tests that would fail if the claimed behavior regressed. Avoid expanding an existing category to hide an unknown failure.

Use focused pull requests and respectful technical feedback. Never include private account keys, customer snapshots or unredacted production data. Every new protocol behavior must identify its reference and explicitly document unsupported cases.
